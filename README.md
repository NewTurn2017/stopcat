# vh — Vibe Health

맥이 느려졌을 때 "무엇이 왜 떠 있는지"를 쉬운 한국어로 보여 주고, 확인을 받은 뒤에만 정리하는 macOS 명령줄 도구입니다.

AI로 서버를 띄우고 여러 에이전트를 돌리다 보면 주인 없는 프로세스, 끝난 테스트가 남긴 에뮬레이터·브라우저, 외부에 열린 포트가 쌓입니다. `vh`는 프로세스 번호(PID) 대신 **프로젝트와 AI 세션 단위**로 맥을 보고, 끄기 전에 **누가 왜 띄웠는지** 설명합니다.

> 이 문서의 화면 예시는 모두 합성 데이터입니다. 실제 값은 맥마다 다릅니다.

## 설치

Rust(1.85 이상)가 필요합니다.

```sh
cargo build --release
# 만들어진 실행 파일: target/release/vh
cp target/release/vh /usr/local/bin/   # 또는 PATH에 있는 아무 폴더
```

관리자 권한(sudo)은 필요 없습니다. 상주 프로그램이나 로그인 항목을 설치하지 않습니다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `vh` (= `vh status`) | 상태 한 화면: 메모리 압력·압축·스왑·부하, 주의할 것, 정리하면 되찾을 수 있는 양 |
| `vh why <번호 \| :포트>` | 그 프로세스를 누가 띄웠는지(자신 → 부모 → … → 시스템), 종류, 프로젝트, 띄운 AI 세션이 살아 있는지 |
| `vh ports` | 기다리는 포트 → 프로그램 → 프로젝트, 외부 노출, 알려진 충돌(AirPlay 5000·7000) |
| `vh fix` | 정리 미리보기. 확인하면 단계적으로 종료 |
| `vh kill <번호 \| :포트>` | 한 대상을 미리보기 후 단계적으로 끄기 |
| `vh snapshot` | 수집 원본을 JSON으로(인자 가림·허용된 환경변수만). 문제 신고용 |

대상 쓰는 법: `:5000`처럼 **콜론을 붙이면 포트**, `4821`처럼 **숫자만 쓰면 프로세스 번호**입니다.

### 공통 옵션

| 옵션 | 뜻 |
|---|---|
| `--json` | 사람용 화면 대신 JSON 한 줄 |
| `--no-cpu` | CPU 사용률을 재지 않음(더 빠름) |
| `--interval-ms <밀리초>` | CPU 사용률을 잴 때 두 번 읽는 간격(기본 250, 50~5000) |
| `--no-color` | 색 없이. `NO_COLOR` 환경변수가 있거나 화면이 터미널이 아니면 자동으로 색 없음 |

### `vh fix` 옵션

| 옵션 | 뜻 |
|---|---|
| `-y`, `--yes` | 묻지 않고 바로 정리 |
| `--only <번호>` | 이 프로세스만(여러 번 쓸 수 있음) |
| `--min-confidence confirmed\|likely` | 이 신뢰도 이상만 |

### `vh kill` 옵션

| 옵션 | 뜻 |
|---|---|
| `-y`, `--yes` | 묻지 않고 바로 끄기 |
| `--tree` | 자식 프로세스도 함께(자식부터) 끄기 |

## 화면 읽는 법

- **첫 줄**은 언제나 메모리 상태입니다. 위기가 아니면 "정상"이라고 먼저 말합니다. 사용률(%)만으로는 경고하지 않습니다.
- **주의**: 무거운 프로세스·AI 세션. **고아**: 띄운 쪽(터미널·AI 세션)이 끝났는데 남은 것. **잔재**: 테스트가 남긴 에뮬레이터·브라우저·좀비 등. **노출**: 같은 와이파이의 다른 기기에서도 접속되는 포트. **충돌**: 자주 부딪히는 포트.
- **신뢰도**: 확실 · 가능성 높음 · 가능성 있음. "가능성 있음"은 화면과 정리 대상에서 기본으로 뺍니다.

## 안전 원칙

1. **미리보기가 기본입니다.** `vh fix`·`vh kill`은 무엇을, 왜, 어떻게 끌지 먼저 보여 줍니다.
2. **확인 없이 끄지 않습니다.** 터미널에서 `y`라고 답하거나 `--yes`를 줄 때만 실행합니다. 터미널이 아닌 곳(스크립트·파이프)에서 `--yes` 없이 부르면 미리보기만 하고 끝납니다.
3. **신뢰도 기준**: 확인하고 실행할 때는 "확실 + 가능성 높음", `--yes`로 목록을 안 보고 실행할 때는 "확실"만 정리합니다. `--only <번호>`로 직접 고른 대상은 신뢰도와 상관없이 포함합니다(보호 규칙은 그대로). `--min-confidence`를 주면 그것이 우선합니다.
4. **단계적으로 끕니다**: (멈춰 있으면 풀기) → 정상 종료 신호 → 3초 기다림 → 그래도 남으면 강제 종료. 자식까지 끌 때는 자식부터 끕니다.
5. **AI 에이전트 세션(claude·codex·omo)은 끄지 않습니다.** 끄면 대화 맥락이 사라집니다. 무거우면 핸드오프를 저장한 뒤 직접 다시 켜도록 권합니다.
6. **실행 직전에 다시 확인합니다.** 미리보기 뒤 그 번호가 다른 프로그램에 다시 쓰였으면(시작 시각이 다르면) 건드리지 않습니다.

### 보호 규칙

아래에 걸리면 `vh`는 끄지 않고 이유를 보여 줍니다.

| 규칙 | 끄지 않는 대상 |
|---|---|
| R01 | launchd·커널(번호 1 이하) |
| R02 | vh 자신 |
| R03 | vh를 띄운 터미널·셸·에이전트 세션(조상) |
| R04 | 다른 사용자·시스템 계정의 프로세스 |
| R05 | macOS 시스템 구성 요소(`/System/` 등) |
| R06 | 앱의 XPC 서비스·확장 |
| R07 | 앱 번들 안의 앱·헬퍼(앱을 종료하면 함께 정리됨) |
| R08 | AI 에이전트 세션·GUI 앱·가상 머신·데이터베이스 |
| R09 | 아래에 살아 있는 에이전트 세션이나 앱이 있는 대상 |
| R10 | 좀비(이미 끝남, 부모 앱을 다시 시작해야 사라짐) |
| R11 | 자동 조치 대상이 아닌 발견(핸드오프 권장·부모 재시작·검토). 검토는 `--only`로 직접 고르면 정리 |
| R12 | 우선순위 낮추기(이번 버전의 `vh`에는 켜는 옵션이 없음) |
| R13 | 정한 신뢰도 기준보다 낮은 발견 |
| R14 | 미리보기 뒤 시작 시각이 달라진 대상(번호 재사용) |
| R15 | 실행 중 찾은 자식이 진짜 자식인지 시작 시각으로 확인되지 않는 경우 |

### 기록 위치

정리를 실행하면 다음을 남깁니다(미리보기만 할 때는 아무것도 쓰지 않습니다).

- 감사 로그: `~/Library/Application Support/vibe-health/audit.jsonl` — 언제, 무엇에, 어떤 신호를 보냈고 결과가 어땠는지
- 되살리기 정보: `~/Library/Application Support/vibe-health/revive/` — 끄기 전의 실행 파일·인자·폴더(권한 0600). 이번 버전은 기록만 하고 되살리기 명령은 아직 없습니다

`VH_STATE_DIR` 환경변수로 이 폴더를 바꿀 수 있습니다.

## 개인정보

- 환경변수는 정해진 허용 목록(예: `CLAUDE_PID`, `TERM_PROGRAM`, `VIRTUAL_ENV`)만 읽어 둡니다. 나머지 값은 읽는 즉시 버립니다.
- 화면과 JSON에 나오는 실행 인자는 비밀처럼 보이는 값(`--api-key` 같은 옵션의 값, 토큰, `Bearer` 뒤의 값, URL의 사용자 정보 등)을 `<가림>`으로 바꿉니다. 키 이름은 남겨서 무엇이 가려졌는지 알 수 있습니다.
- 어떤 정보도 맥 밖으로 보내지 않습니다.

## 하지 않는 것

- `purge` 같은 "RAM 정리"
- 사용률(%)만 보고 하는 경보
- 확인 없는 강제 종료(`kill -9`)
- 관리자 권한(sudo) 요구
- 파일·폴더 자동 삭제, 디스크 정리
- 상주 데몬, 로그인 항목·LaunchAgent 설치, 메뉴바 앱, 전체 화면 UI
- 꺼진 프로그램 되살리기 실행(기록만 함)

## 종료 코드와 JSON

- 종료 코드: `0` 정상(미리보기만 하고 끝난 경우, 보호 규칙으로 거부된 경우 포함), `1` 사용법 오류·대상 없음·내부 오류.
- `--json` 최상위 키:

| 명령 | 키 |
|---|---|
| `vh` | `schema_version`, `report`, `host`, `memory`, `limits`, `timings_ms` |
| `vh why` | `schema_version`, `taken_at_unix_ms`, `query`, `explanations` |
| `vh ports` | `schema_version`, `taken_at_unix_ms`, `listeners`, `findings` |
| `vh fix` | `schema_version`, `taken_at_unix_ms`, `mode`, `plan`, `outcomes`, `audit_log`, `state_dir` |
| `vh kill` | 위 `vh fix` 키 + `target` |
| `vh snapshot` | 수집 결과(`Snapshot`) 필드 그대로 |
| 오류 | `schema_version`, `error`(`code`, `message_ko`) |

`mode`는 `nothing_to_do`(정리할 것 없음), `non_interactive_preview`(확인 없이 미리보기만), `declined`(취소), `executed`(실행함) 중 하나입니다.

## 문제 신고

`vh snapshot --json > snapshot.json`으로 받은 파일을 함께 보내 주세요. 인자 속 비밀값은 가려지지만, 폴더 이름·프로그램 이름은 그대로 들어 있으니 보내기 전에 한 번 훑어보세요.
