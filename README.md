# StopCat — 필요 없는 것만 멈추는 맥 정리 도구

맥이 느려졌을 때 "무엇이 왜 떠 있는지"를 쉬운 한국어로 보여 주고, 확인을 받은 뒤에만 정리하는 macOS 도구입니다. 화면을 띄워 두면 **지킴이**가 필요 없는 것과 되찾을 수 있는 양을 근거와 함께 보고하고, 맥이 불안정할 때만 '필요 없음'이 확실한 것을 정리합니다. 지금 쓰고 있는 것은 끄지도, 느리게 하지도 않습니다.

AI로 서버를 띄우고 여러 에이전트를 돌리다 보면 주인 없는 프로세스, 끝난 테스트가 남긴 에뮬레이터·브라우저, 외부에 열린 포트가 쌓입니다. `stopcat`은 프로세스 번호(PID) 대신 **프로젝트와 AI 세션 단위**로 맥을 보고, 끄기 전에 **누가 왜 띄웠는지** 설명합니다.

> 이 문서의 화면 예시는 모두 합성 데이터입니다. 실제 값은 맥마다 다릅니다.

## stopcat 하나로 쓰기

터미널에서 `stopcat` 만 치면 됩니다. 전체 화면이 뜨고, 방향키로 고르고 Enter로 정리합니다.

- **처음 실행**하면 지킴이가 무엇을 자동으로 하는지 한 화면으로 보여 줍니다. Enter = 안정화 자동으로 시작, n = 보고만. 고른 값은 저장되고, 설정 화면(4)에서 언제든 바꿀 수 있습니다.
- 맨 위 두 줄은 메모리 상태와 되찾을 수 있는 양(확보 가능 · 확인하면 · 직접 하면)입니다. 지킴이 상태(수준, 평소 보고만·불안정·일시정지·차단기, 마지막 확인 시각)는 키 줄 바로 위에 있습니다.
- 화면은 네 개입니다: **1 보고**(필요 없음 → 확인 필요 → 일하는 중 → 직접 하면 확보 순서, 줄마다 근거 요약), **2 포트**, **3 자동 처리 기록**(지킴이가 한 일: 시각·무엇을·왜·되찾은 양), **4 설정**.
- 목록의 '지킴이' 칸: `정리 추천`, `불안정 시 자동`(평소엔 보고만, 불안정해지면 지킴이가 정리), `자동 예정 1/2`(불안정할 때만, 연속 확인 중), `확인 필요`, `건드리지 않음`(지금 쓰고 있음), `직접 하면 확보`, `앱 재시작 필요`, `우선순위 낮춤`(직접 낮춘 것).
- 창이 80×24보다 작으면 "창을 조금 키워 주세요"만 보입니다.

### 키

| 키 | 하는 일 |
|---|---|
| ↑ ↓ (또는 j k) | 목록에서 이동 |
| 스페이스 | 여러 개 고르기(다시 누르면 풀기) |
| Enter | 고른 것(없으면 지금 줄) 정리: 미리보기 → `y` 실행 / `n` 취소. 끄지 않는 이유(보호 규칙)도 보여 줍니다. 일하는 중·확인 필요를 고르면 경고를 보여 줍니다 |
| c | 추천 전부 정리: 필요 없음 구역만 미리보기 → `y`. 확인 필요·일하는 중은 넣지 않습니다 |
| d | 지금 줄의 우선순위 낮추기(끄지 않음, 미리보기 → `y`) |
| Tab, ← →, 1~4 | 화면 바꾸기 |
| w | 지금 줄을 누가 왜 띄웠는지 자세히 |
| a | 지킴이 수준 바꾸기(적극 자동으로 올릴 때는 한 번 더 묻습니다) |
| p | 지킴이 잠깐 멈춤 / 다시 시작 |
| r | 차단기 풀기(자동 종료 다시 켜기) |
| u | 직접 낮춘 우선순위 되돌리기 |
| ? | 도움말 |
| q, Esc, Ctrl+C | 끝내기(직접 낮춘 우선순위를 되돌리고 끝납니다) |

## 지킴이

화면이 열려 있는 동안 지킴이가 5초마다(메모리 압력이 높으면 2초마다) 맥을 확인하고, 평소에는 보고만 하고, 맥이 불안정할 때(메모리 압력 주의 이상 또는 스왑이 빠르게 늘 때)만 고른 수준대로 정리합니다. 화면을 닫으면 지킴이도 멈춥니다(로그인할 때 자동으로 켜기·화면 없이 돌리기는 다음 버전).

| 수준 | 자동으로 하는 일 |
|---|---|
| 보고만 | 자동으로 정리하지 않습니다. 화면과 알림으로 보고하고, c 한 번으로 추천 항목을 정리할 수 있습니다 |
| **안정화 자동**(기본) | 맥이 불안정할 때만, '필요 없음' 구역에서 확실한 MCP 서버·개발 서버·언어 서버·파일 감시기·헤드리스 브라우저·에이전트 백엔드 가운데 생긴 지 10분이 넘고, 그 뒤 2분 동안 계속 안 쓰는 것이 확인된 것만, 두 번 연속 같은 판정일 때 정상으로 돌아올 만큼만 정리합니다. 그래서 첫 자동 정리는 생긴 지 약 12분 뒤부터 일어날 수 있습니다 |
| 적극 자동 | 불안정할 때 '가능성 높음'과 더 넓은 종류까지 정리합니다. 에뮬레이터처럼 일부러 띄워 둔 것도 꺼질 수 있습니다 |

- 어떤 수준에서도 **지금 쓰고 있는 것(주인 세션이 살아 있음, 터미널이 붙음, 연결된 상대가 있음, CPU·디스크를 쓰는 중, 생긴 지 10분 미만)은 끄지도 느리게 하지도 않습니다.** CPU 100%여도 마찬가지입니다. AI 대화 세션·앱·시스템·가상 머신·DB도 자동으로 끄지 않습니다.
- 자동 우선순위 낮추기는 없습니다. 우선순위는 화면에서 d로 직접 낮출 때만 바뀝니다.
- 자동으로 끄는 것은 규칙상 "확실"하고, 고른 종류에 속하고, 생긴 지 10분이 넘은 뒤 2분 동안 계속 안 쓰는 것이 확인되고, 같은 프로세스가 두 번 연속 같은 판정을 받은 것뿐입니다.
- 10분에 5개를 넘게 끄려 하면 **차단기**가 열려 그 뒤로는 보고만 합니다. `r`로 풀 수 있습니다.
- 자동으로 한 일은 '자동 처리 기록' 화면과 감사 로그에 남습니다. macOS 알림은 맥이 불안정해졌을 때(되찾을 수 있는 양 요약)와 자동으로 정리했을 때만 보냅니다.
- 직접 낮춘 우선순위는 `u`로 하나씩, 또는 화면을 닫을 때 한꺼번에 되돌립니다. `kill -9`처럼 stopcat을 강제로 죽이면 되돌리지 못하고 남을 수 있습니다(그 프로그램을 다시 시작하면 원래대로 돌아옵니다).

## 설치

Rust(1.88 이상)가 필요합니다.

```sh
cargo build --release
# 만들어진 실행 파일: target/release/stopcat
cp target/release/stopcat /usr/local/bin/   # 또는 PATH에 있는 아무 폴더
```

관리자 권한(sudo)은 필요 없습니다. 상주 프로그램이나 로그인 항목을 설치하지 않습니다.

## 스크립트·AI용 명령

터미널이 아닌 곳(파이프·스크립트·AI 에이전트)에서 `stopcat`을 부르면 전체 화면 대신 아래 글자·JSON 출력이 나옵니다. 터미널에서도 `--plain`이나 하위 명령을 주면 같습니다.

| 명령 | 하는 일 |
|---|---|
| `stopcat --plain` (= `stopcat status`, 터미널이 아닐 때의 `stopcat`) | 상태 한 화면: 메모리 상태, 되찾을 수 있는 양, 필요 없음·확인 필요·일하는 중·직접 하면 확보 구역별 목록과 근거 |
| `stopcat why <번호 \| :포트>` | 그 프로세스를 누가 띄웠는지(자신 → 부모 → … → 시스템), 종류, 프로젝트, 띄운 AI 세션이 살아 있는지 |
| `stopcat ports` | 기다리는 포트 → 프로그램 → 프로젝트, 외부 노출, 알려진 충돌(AirPlay 5000·7000) |
| `stopcat fix` | '필요 없음' 구역만 정리 미리보기. 확인하면 단계적으로 종료 |
| `stopcat kill <번호 \| :포트>` | 한 대상을 미리보기 후 단계적으로 끄기 |
| `stopcat snapshot` | 수집 원본을 JSON으로(인자 가림·허용된 환경변수만). 문제 신고용 |

대상 쓰는 법: `:5000`처럼 **콜론을 붙이면 포트**, `4821`처럼 **숫자만 쓰면 프로세스 번호**입니다.

### 공통 옵션

| 옵션 | 뜻 |
|---|---|
| `--json` | 사람용 화면 대신 JSON 한 줄 |
| `--plain` | 전체 화면 대신 글자 상태 화면 |
| `--no-cpu` | CPU 사용률을 재지 않음(더 빠름) |
| `--interval-ms <밀리초>` | CPU 사용률을 잴 때 두 번 읽는 간격(기본 250, 50~5000) |
| `--no-color` | 색 없이. `NO_COLOR` 환경변수가 있거나 화면이 터미널이 아니면 자동으로 색 없음 |

### `stopcat fix` 옵션

| 옵션 | 뜻 |
|---|---|
| `-y`, `--yes` | 묻지 않고 바로 정리 |
| `--only <번호>` | 이 프로세스만(여러 번 쓸 수 있음). 확인 필요·일하는 중이어도 고를 수 있고 경고를 보여 줍니다 |
| `--min-confidence confirmed\|likely` | 이 신뢰도 이상만 |

### `stopcat kill` 옵션

| 옵션 | 뜻 |
|---|---|
| `-y`, `--yes` | 묻지 않고 바로 끄기 |
| `--tree` | 자식 프로세스도 함께(자식부터) 끄기 |

## 화면 읽는 법

- **첫 줄**은 언제나 메모리 상태입니다. 위기가 아니면 "정상"이라고 먼저 말합니다. 사용률(%)만으로는 경고하지 않습니다.
- **필요 없음**: 띄운 쪽이 끝났고 지금 쓰지 않는 것(정리 추천). **확인 필요**: 띄운 쪽이 끝났지만 쓰고 있는 흔적이 있거나, 띄운 쪽은 살아 있지만 안 쓰는 듯한 것(보고만). **일하는 중**: 지금 쓰고 있는 것(건드리지 않음). **직접 하면 확보**: AI 세션 재시작, 가상 머신·로컬 LLM, 좀비처럼 stopcat이 끄지 않지만 직접 하면 되찾는 것. **노출**: 같은 와이파이의 다른 기기에서도 접속되는 포트. **충돌**: 자주 부딪히는 포트.
- **신뢰도**: 확실 · 가능성 높음 · 가능성 있음. 자세히 칸과 미리보기에 보입니다. "가능성 있음"도 화면에는 구역대로 보이고, 정리 대상에서는 기본으로 뺍니다.
- 한 줄에 여러 개를 모아 보여 줄 때 같은 이름은 `×2`처럼 묶고, 줄에 다 못 넣은 것은 `외 N건`으로 셉니다.

## 안전 원칙

1. **미리보기가 기본입니다.** `stopcat fix`·`stopcat kill`은 무엇을, 왜, 어떻게 끌지 먼저 보여 줍니다.
2. **확인 없이 끄지 않습니다.** 터미널에서 `y`라고 답하거나 `--yes`를 줄 때만 실행합니다. 터미널이 아닌 곳(스크립트·파이프)에서 `--yes` 없이 부르면 미리보기만 하고 끝납니다.
3. **정리 기준**: `stopcat fix`와 c는 '필요 없음' 구역만 봅니다. 그 안에서 확인하고 실행할 때는 "확실 + 가능성 높음", `--yes`로 목록을 안 보고 실행할 때는 "확실"만 정리합니다. `--only <번호>`로 직접 고른 대상은 구역·신뢰도와 상관없이 포함합니다(보호 규칙은 그대로). `--min-confidence`를 주면 그것이 우선합니다.
4. **단계적으로 끕니다**: (멈춰 있으면 풀기) → 정상 종료 신호 → 3초 기다림 → 그래도 남으면 강제 종료. 자식까지 끌 때는 자식부터 끕니다.
5. **AI 에이전트 세션(claude·codex·omo)은 끄지 않습니다.** 끄면 대화 맥락이 사라집니다. 무거우면 핸드오프를 저장한 뒤 직접 다시 켜도록 권합니다.
6. **실행 직전에 다시 확인합니다.** 미리보기 뒤 그 번호가 다른 프로그램에 다시 쓰였으면(시작 시각이 다르면) 건드리지 않습니다.
7. **지킴이도 같은 규칙을 거칩니다.** 자동 정리도 아래 보호 규칙과 단계적 종료를 그대로 지나고, 화면에서 확인한 정리와 자동 정리는 한 곳(지킴이)에서만 신호를 보냅니다.

### 보호 규칙

아래에 걸리면 `stopcat`은 끄지 않고 이유를 보여 줍니다.

| 규칙 | 끄지 않는 대상 |
|---|---|
| R01 | launchd·커널(번호 1 이하) |
| R02 | stopcat 자신 |
| R03 | stopcat을 띄운 터미널·셸·에이전트 세션(조상) |
| R04 | 다른 사용자·시스템 계정의 프로세스 |
| R05 | macOS 시스템 구성 요소(`/System/` 등) |
| R06 | 앱의 XPC 서비스·확장 |
| R07 | 앱 번들 안의 앱·헬퍼(앱을 종료하면 함께 정리됨) |
| R08 | AI 에이전트 세션·GUI 앱·가상 머신·데이터베이스 |
| R09 | 아래에 살아 있는 에이전트 세션이나 앱이 있는 대상 |
| R10 | 좀비(이미 끝남, 부모 앱을 다시 시작해야 사라짐) |
| R11 | 자동 조치 대상이 아닌 발견(핸드오프 권장·부모 재시작·검토). 검토는 `--only`로 직접 고르면 정리 |
| R12 | 우선순위 낮추기(`stopcat fix`에는 켜는 옵션이 없음. 전체 화면에서 d 로 직접 고를 때만 낮춤) |
| R13 | 정한 신뢰도 기준보다 낮은 발견 |
| R14 | 미리보기 뒤 시작 시각이 달라진 대상(번호 재사용) |
| R15 | 실행 중 찾은 자식이 진짜 자식인지 시작 시각으로 확인되지 않는 경우 |
| R16 | 한 번에 정리할 수 있는 개수(기본 50개)를 넘은 나머지. 다시 실행하면 이어서 정리 |

### 기록 위치

정리를 실행하면 다음을 남깁니다(미리보기만 할 때는 아무것도 쓰지 않습니다).

- 설정: `~/Library/Application Support/stopcat/config.json` — 처음 실행에서 고른 지킴이 수준과 확인 간격

- 감사 로그: `~/Library/Application Support/stopcat/audit.jsonl` — 언제, 무엇에, 어떤 신호를 보냈고 결과가 어땠는지
- 되살리기 정보: `~/Library/Application Support/stopcat/revive/` — 끄기 전의 실행 파일·인자·폴더(권한 0600). 이번 버전은 기록만 하고 되살리기 명령은 아직 없습니다

`STOPCAT_STATE_DIR` 환경변수로 이 폴더를 바꿀 수 있습니다.

## 환경 변수

| 변수 | 뜻 |
|---|---|
| `STOPCAT_GUARD_LEVEL=notify\|safe\|aggressive` | 지킴이 수준을 정합니다(notify = 보고만, safe = 안정화 자동, aggressive = 적극 자동). 설정 파일보다 우선하고, 화면에서는 바꿀 수 없습니다. 알아볼 수 없는 값이면 보고만으로 실행합니다 |
| `STOPCAT_STATE_DIR` | 설정·감사 로그·되살리기 정보 폴더 |
| `STOPCAT_NOTIFY=off` | macOS 알림을 보내지 않습니다 |
| `STOPCAT_E2E_ALLOW_PIDS` | 시험용 잠금: 적힌 프로세스 번호에만 신호를 보냅니다(쉼표로 구분, 비어 있으면 모두 막음) |
| `STOPCAT_E2E_FORCE_HEALTH=watch\|critical` | 시험용. `STOPCAT_E2E_ALLOW_PIDS`가 함께 있을 때만 읽고, 지킴이가 맥을 불안정으로 보게 합니다(화면의 실제 건강 표시는 그대로). 평소에는 쓰지 마세요 |
| `NO_COLOR` | 색 없이(전체 화면은 흑백) |

## 개인정보

- 환경변수는 정해진 허용 목록(예: `CLAUDE_PID`, `TERM_PROGRAM`, `VIRTUAL_ENV`)만 읽어 둡니다. 나머지 값은 읽는 즉시 버립니다.
- 화면과 JSON에 나오는 실행 인자는 비밀처럼 보이는 값(`--api-key` 같은 옵션의 값, 토큰, `Bearer` 뒤의 값, URL의 사용자 정보 등)을 `<가림>`으로 바꿉니다. 키 이름은 남겨서 무엇이 가려졌는지 알 수 있습니다.
- 어떤 정보도 맥 밖으로 보내지 않습니다.

## 하지 않는 것

- `purge` 같은 "RAM 정리"
- 사용률(%)만 보고 하는 경보
- 확인 없는 강제 종료(`kill -9`)
- 지금 쓰고 있는 프로세스 자동 종료, 자동 우선순위 낮추기
- 관리자 권한(sudo) 요구
- 파일·폴더 자동 삭제, 디스크 정리
- 상주 데몬, 로그인 항목·LaunchAgent 설치(로그인할 때 자동 실행은 다음 버전), 메뉴바 앱
- 꺼진 프로그램 되살리기 실행(기록만 함)

## 종료 코드와 JSON

- 종료 코드: `0` 정상(미리보기만 하고 끝난 경우, 보호 규칙으로 거부된 경우 포함), `1` 사용법 오류·대상 없음·내부 오류. 전체 화면은 끝내기 키로 끝나면 `0`, 신호(SIGTERM 등)로 끝나면 `128 + 신호 번호`, 끝내는 중 Ctrl+C를 한 번 더 누르면 `130`.
- `--json` 최상위 키(`schema_version` 2. 1에서 바뀐 점: report.findings[].section(구역), report.classified[].usage(사용 판정), report.totals의 구역별 확보량 세 값이 더해졌고, 발견 종류 runaway는 high_cpu로 바뀌었습니다):

| 명령 | 키 |
|---|---|
| `stopcat --json` | `schema_version`, `report`, `host`, `memory`, `limits`, `timings_ms` |
| `stopcat why` | `schema_version`, `taken_at_unix_ms`, `query`, `explanations` |
| `stopcat ports` | `schema_version`, `taken_at_unix_ms`, `listeners`, `findings` |
| `stopcat fix` | `schema_version`, `taken_at_unix_ms`, `mode`, `plan`, `outcomes`, `audit_log`, `state_dir` |
| `stopcat kill` | 위 `stopcat fix` 키 + `target` |
| `stopcat snapshot` | 수집 결과(`Snapshot`) 필드 그대로 |
| 오류 | `schema_version`, `error`(`code`, `message_ko`) |

`mode`는 `nothing_to_do`(정리할 것 없음), `non_interactive_preview`(확인 없이 미리보기만), `declined`(취소), `executed`(실행함) 중 하나입니다.

## 문제 신고

`stopcat snapshot --json > snapshot.json`으로 받은 파일을 함께 보내 주세요. 인자 속 비밀값은 가려지지만, 폴더 이름·프로그램 이름은 그대로 들어 있으니 보내기 전에 한 번 훑어보세요.
